Реестр плагинов
В контексте работы представляет собой контракт, который необходимо поддержать для использования сервиса в качестве реестра плагинов
Реестр плагина должен хранить плагины и реализовывать методы, описанные в спецификации

Реестр плагинов должен хранить версии плагинов и возвращать вторым методом плагин согласно переданной версии
Версии плагина должны быть неизменяемыми любое изменение в конфигурации плагина должно порождать новую версию плагина. Версия плагина является постоянной.

Контакт:
```
GET
(Получение списка плагинов)
/v1/plugins?limit=?&page=?

(Получение версий плагина)
GET
/v1/plugins/{id}/versions?limit=?&page=?

(Получение плагина определенной версии)
GET
/v1/plugins/{id}/versions/{version}

(Получение конфигурации плагина определенной версии)
GET
/v1/plugins/{id}/versions/{version}/manifest
```
пагинация начинается с 1. лимит по умолчанию 20
Формат ответа с пагинацией:
```json
{
  "items": [],
  "page": 1,
  "limit": 20,
  "totalItems": 0,
  "totalPages": 0
}
```

Стек реетра:
- Язык фреймворк: Java + Spring.
  Обоснование: Данный стек позволит создать с минимальными усилиями CRUD сревис, представляющий собой реестр
- База данных: PostgreSQL
  Обоснование: Плагины имеют структуру, но множество из их полей необязательны или имеют вложенную структуру, поэтому удобнее хранить записи о плагинах в json полях базы данных
